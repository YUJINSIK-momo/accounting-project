# 경비 · 지출 회계 데모

그룹웨어 회계 모듈(경비청구 · 품의 · 지출결의 · 전표처리)의 화면 흐름을 참고해 만든 정적 웹 앱입니다. 서버 없이 브라우저 `localStorage` 에 데이터를 저장하고, 들어 있는 회사 · 사람 · 금액은 모두 가상의 예시입니다.

**배포 주소: https://yujinsik-momo.github.io/accounting-project/**

## 기능

| 메뉴 | 내용 |
|---|---|
| 매뉴얼 | 헤더의 「매뉴얼」 — 메뉴마다 흐름 · 단계 · 스크린샷을 노션 문서처럼 정리(`src/data/manual.ts`, 스크린샷은 `npm run manual:shots`) |
| AI 어시스턴트 | 오른쪽 아래 버튼. 버튼 길잡이로 품의 · 경비 · 결재함 · 예산 · 경비 합계 · 급여 · 부가세 · 검색을 끝까지 진행. 글로 요청해도 같은 흐름으로 이어지고, 쓰기는 확인 카드에서 눌러야 실행 |
| 홈 | 내 미결 · 진행 중 상신 · 이번 달 경비 · 미청구 카드 · 최근 실수령액, 빠른 경비 입력 · 빠른 품의, 카드 · 현금영수증 · 세금계산서 연동 안내 |
| 경비현황분석 | 월 청구액, 전월 대비, 결재 대기, 미지급 잔액. 용도 · 조직 · 기간별 막대 |
| 결재함 | 경비청구 · 품의서 · 지출결의서 승인 / 반려 |
| 경비청구작성 | STEP1 카드 내역 조회 → STEP2 용도 · 내용 입력과 검증 → STEP3 결재상신 |
| 청구내역 · 경비부서집계표 | 사원별 청구서, 부서 · 사원별 소계와 직전 청구 대비 증감 |
| 사용 점검 | 제한시간(23~06시 · 주말) 사용, 같은 날 같은 가맹점 중복 사용 |
| 품의서 · 지출결의서 | 품의 금액 대비 집행액, 증빙별 부가세 처리, 분개 미리보기 |
| 전표처리 | 경비전표 · 지출결의전표 발행 / 취소, 지급처리 |
| 분개장 · 총계정원장 · 합계잔액시산표 | 발행된 전표만 반영, 대차 일치 확인 |
| 급여대장 · 급여명세서 | 기본급 · 수당 · 상여, 4대보험 · 원천세 계산, 확정 시 명세서 알림, 급여 전표, 명세서 PDF |
| 퇴직금 시뮬레이션 | 최근 3개월 임금 · 상여 · 연차수당으로 1일 평균임금과 퇴직금 계산식 |
| 연말정산 | 근로소득 원천징수부, 공제 자료를 넣는 모의 계산(환급 · 추가납부) |
| 세금계산서 · 부가세 | 매입 계산서 ↔ 지출결의 연결, 매출 발행 · 수정발행, 신고 기간별 납부세액 |
| 예산 대비 집행 | 부서 × 계정 연간 예산, 발행 전표(집행) · 결재 중 문서(진행) · 잔액 · 집행률. 지출결의서 · 경비청구 작성 화면에 예산 잔액 표시 |
| 재무제표 | 발행 전표로 만든 손익계산서(기간) · 재무상태표(기준일), PDF · 엑셀 |
| 기초정보관리 | 용도 → 계정과목 연결, 계정과목 · 거래처 · 카드 · 조직(법인 › 본부 › 팀) · 사원 · 요율 |

모든 주요 표에 「엑셀 내보내기」(.xlsx)가 있고, 품의서 · 지출결의서 · 경비청구서에 파일을 첨부할 수 있습니다(브라우저 IndexedDB 에 저장).

### 결재 흐름

기안자가 조직도(법인 › 본부 › 팀)에서 결재 · 합의 · 수신 · 참조를 골라 결재선을 지정해 상신하면(자주 쓰는 결재선은 개인결재라인으로 저장) 결재자가 차례로 승인합니다. 종결되면 수신자가 접수하고, 참조자는 열람합니다. 반려하면 기안자에게 돌아오고, 아무도 결재하지 않았으면 기안자가 회수할 수 있습니다. 금액이 직급별 전결 한도 이하면 중간 결재자가 전결로 종결할 수 있고, 남은 칸은 사선으로 표시됩니다. 단계마다 해당 사람에게 알림(헤더의 종)이 가고, 결재란에는 승인한 사람의 서명 도장이 찍힙니다. 문서는 「인쇄 · PDF 저장」으로 PDF 를 만들 수 있고, 「메일로 보내기」는 메일 앱을 엽니다(이 앱은 서버가 없어 메일을 직접 보내지 않습니다).

오른쪽 위 사용자 선택으로 결재자 · 수신자 입장을 바꿔 볼 수 있습니다.

검증 규칙은 `src/lib/journal.ts`, 결재 흐름은 `src/lib/approval.ts`, 급여 · 세금 계산은 `src/lib/payroll.ts` 에 있습니다. 4대보험 요율 · 원천세는 예시 계산이므로 실제 지급 전에 고시값으로 확인해야 합니다. 부적합(용도 · 내용 · 금액 누락 등)은 상신을 막고, 확인필요(심야 · 주말 · 중복 · 부가세 10% 불일치)는 표시만 합니다.

### AI 어시스턴트

- 모든 답은 다음에 누를 버튼으로 끝나고, 흐름의 상태는 버튼이 들고 다닌다(`src/lib/assistantFlow.ts`). 고르던 단계에서 글로 답하면 그 단계를 이어 간다.
- 글 요청은 규칙(`src/lib/assistant.ts`)으로 의도를 고른다. 설정에서 본인 Claude API 키를 넣으면 AI 모델이 의도를 고른다(`src/lib/assistantLlm.ts`, 키는 탭 세션에만 저장).
- 답의 숫자는 늘 앱 데이터로 계산하고, 저장 · 상신은 확인 카드에서 사용자가 눌러야 한다.

## 나중에 붙일 것

| 항목 | 붙일 자리 |
|---|---|
| 법인(회계단위)별 장부 | `Company` 는 조직도에만 쓰인다. 전표 · 문서에 `companyId` 를 넣고 `postedLines` · 재무제표를 법인별로 거르면 된다 |
| 관리항목 확장 | 분개 줄에 `dept` · `project` 가 있다(`VoucherLine`). 거래처 · 카드 등 항목을 더하고 원장 · 예산에서 거른다 |
| 부가세 · 원천세 신고서 양식 | 부가세는 `TaxInvoices` 의 신고 기간 집계, 원천세는 급여대장(`PayrollRun`)의 소득세 · 지방소득세 합계를 신고서 양식(`components/app/print.tsx` 의 `Paper`)에 옮긴다 |
| 회사 부담 4대보험 · 결산 조정 | 급여 전표(`payrollJournal`)에 회사 부담분, 재무제표에 감가상각 · 대손 · 법인세를 더한다 |
| 카드 · 홈택스 실제 연동 | 백엔드 서버가 필요하다. 홈 화면의 연동 안내 참고 |

## 디자인 시스템

화면은 yuyu UI 를 밝은 테마(`src/styles/yuyu-light.css`, 같은 토큰 이름에 라이트 값만 덮어씀)로 씁니다. `src/components/yuyu/` 와 `src/styles/yuyu-tokens.css` 는 [Backend-Developer-Portfolio](https://github.com/YUJINSIK-momo/Backend-Developer-Portfolio) 의 yuyu 컴포넌트를 그대로 가져온 것이고, 토큰 이름 규칙은 [Design-Dev-Infra-Pipeline](https://github.com/YUJINSIK-momo/Design-Dev-Infra-Pipeline) 을 따릅니다. 표 · 입력 · 모달처럼 yuyu 에 없는 부품은 `src/components/app/ui.tsx` 에 yuyu 토큰만으로 만들었습니다.

## 실행

```bash
npm ci
npm run dev      # http://localhost:5173/accounting-project/
npm run build
```

`main` 에 push 하면 GitHub Actions 가 빌드해 GitHub Pages 로 배포합니다. 화면 오른쪽 위 「초기화」를 누르면 예시 데이터로 돌아갑니다.
